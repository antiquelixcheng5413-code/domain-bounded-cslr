# Stage Report — P173 运动线索探针（帧差 concat 到 VAC 2D）

**日期**：2026-10-30 ｜ **状态**：✗ 判死（运动线索无增益）
**对照基线**：P150（VAC@160+3ch RGB，dev 53.73；含 word_head 0.3 正则；去 head 基线≈55.88）

---

## 1. 动机与假设

**依据等级：无（我拍的，轻量工程探针）**
TFNet 论文同代码硬编码的各骨干 dev WER 显示 CorrNet 是最弱骨干（47.2），换 3D 骨干补不了我们 8.6pp 的训练/数据赤字（见 MEMORY.md CorrNet 核查）。
轻量替代思路：**把运动线索（前后帧差）作为额外通道 concat 到现有 VAC 2D 骨干**（RGB 3ch + 前/后帧差 2ch = 5ch），几乎零架构改动，直接测"运动线索是否有用"。

- 假设 H1：帧差提供 VAC 缺失的时序运动信息 → dev 显著低于 P150 同期（≥2pp 且持续）。
- 假设 H0：帧差对 2D 卷积骨干无额外判别力 → 与 P150 持平。

## 2. 方法

- 模型：`VAC`（resnet18 骨干），monkeypatch `conv1` 由 3→5 通道（拷贝 ImageNet 前 3 通道权重，后 2 通道随机初始化）。
- 数据：`FlowRGBSeqDataset` 拼 `[RGB_t, |RGB_t − RGB_{t-1}|, |RGB_t − RGB_{t+1}|]` → 5 通道；`flow_collate` 动态通道。
- 训练：复用 P150 条件（lr=1e-4, wd=1e-4, batch=2, MultiStepLR[35,45]@55, bf16, CTC-only，**无 word_head**）。
- 脚本：`tools/blank_gov/p173_flow_probe.py`（冒烟通过：conv1=5ch、样本 [212,5,160,160]、前向 out[0]=(58,2,3516)、单步反向 OK）。
- 修复记录：
  - 首跑崩于 ep05 存盘 `TypeError`（格式串 `"%s-ep%02d.pt" % a.tag` 双占位符单参）。commit `bb75cb9` 修为 `% (a.tag, ep)`。
  - `dev_eval` 内 `BLANK_BIAS` 由 0.0 改 **1.0**（P173 同为 VAC 骨干，须与 P150 同解码口径，否则差 ~0.8pp 误导对照）。
  - 加 `--resume` 续跑（防 WorkBuddy 重启杀 WSL 丢进度）；best + 每 5 轮存盘。

## 3. 结果

| epoch | P173（5ch 帧差） | P150（3ch RGB，同期） | 解读 |
|---|---|---|---|
| ep01 | 82.83（旧 bias=0.0） | 81.56 | 旧口径，参考 |
| ep02 | 78.08（旧，best） | ~78–79 | 旧口径，参考 |
| **ep03** | **78.47（新 bias=1.0）** | **≈78.3**（ep1/4 插值） | **持平** |
| ep04 | 训练中（~00:05 时未出） | 75.55 | — |

- 旧口径(0.0) ep01–04 轨迹 **82.83 → 78.08 → 79.17 → 80.23**，ep03/04 **反弹**（P150 同期应继续下降）。
- 新口径(1.0) ep03 = 78.47，比旧同轮 ep03(79.17) 好 **0.7pp**，**恰等于 bias 0.0→1.0 的修正量** ⇒ 改善完全来自解码口径对齐，**帧差通道贡献 ≈0**。
- P173 与 P150 同期**打平**；且 P173 未挂 word_head（P150 靠它再降 ~2pp），严格说帧差**中性偏负**。

## 4. 判定

**判死（H0 成立）**：运动线索（前后帧差）对 VAC 判别力无增益，不补 backbone 差距。
- 效率账：续跑后每轮 ~96min（num_workers=0 + 帧差 CPU 算），比 P150 纯 RGB 的 ~57min 多烧 ~70% 时间，换取 0 增益。
- 真天花板维持：**零样本 TFNet@160 = dev 36.81% / test 35.66%**（发布权重，不微调）。
