## 3. 机理

| lr | Δtrain_ctc（vs P123） | 解读 |
|---|---|---|
| 5e-5（P140） | −2.6 ~ −6.2（拟合更深） | 优化走得太深 ⇒ 过拟合加深 |
| 1.5e-4（P141） | 见下 | — |

P141 的 train CTC：ep37 8.84 → ep40 7.98（P123 同期 8.06 → 7.16）
⇒ P141 的训练损失**略高于** P123 ⇒ 大 lr 反而没拟合得更深，
是**收敛不够干净**（与 P137 在短调度下"先好后崩"同类）。

## 6. 附带修：argparse 的 help 字符串会做 `%` 格式化

P142 首次启动失败（重启 2 次都立刻退出），报错：
```
ValueError: badly formed help string
  → TypeError: * wants int
```
原因：`--label-smoothing` 的 help 里写了 `100%` / `48%` / `9%`，
argparse 把 `%` 当格式化占位符。**必须写成 `%%`。**
（`--blank-bias` 的 help 里我当时已用 `77.2%%`，所以只有 LS 那个参数炸了）
⇒ 修好后 `--help` 解析正常，P142 正常启动。

**铁律：argparse 的 help 字符串里所有字面 `%` 都要写成 `%%`；
加完参数后必须跑一次 `--help` 验证。**
