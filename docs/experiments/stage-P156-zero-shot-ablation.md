## Research question

发布 TFNet 权重（resnet34MAM）在我们的 CE-CSL dev 上实测 **33.92%**（224+RGB 原配）。
我们要在这把「干净权重」上**推理时换输入**（不微调、零训练成本），把"落后 20pp"拆成三件独立的事：
1. 分辨率代价：224 → 160 值多少 pp？
2. 通道代价：RGB → BGR 值多少 pp？
3. 叠加（= 我们项目早期在 BGR 下的取舍）值多少 pp？

→ 最终把"骨干缺口"与"分辨率/通道/微调"彻底隔离。

---

## Verdict（判答）

**判活（作为诊断，结论可判）。**

- 门禁通过：`224+RGB = 33.92%`，与历史实测 **+0.00 pp**，证明修正后的评估路径可信。
- 三因子全部被干净数字隔离，且量级差异巨大，远大于噪声基准（1.556pp）：
  - 分辨率代价（224→160，RGB）：**+2.89 pp**（温和，SNR≈1.86，强提示）
  - 通道代价（RGB→BGR，224）：**+43.67 pp**（确凿，SNR≫2）
  - 两者叠加：**+45.46 pp**

> 注意：通道代价是「推理时直接换通道」的**上界**；从头训练会完全适应，且本项目数据近乎灰度（|R−B| 中位 8）并已修复抽帧侧 R/B 颠倒（`--fix-rgb-order`），故训练侧真实通道损失远小于此。

---

## 结果

| 组合 | WER | 生成率 | vs 224+RGB |
|---|---|---|---|
| **224+RGB（基线）** | **33.92%** | 94.9% | — （门禁 +0.00） |
| 160+RGB | 36.81% | 93.3% | +2.89 |
| 224+BGR | 77.59% | 44.6% | +43.67 |
| 160+BGR | 79.38% | 43.2% | +45.46 |

**叠加对照（把"我们为什么落后"彻底拆开）：**

| 配置 | WER | 说明 |
|---|---|---|
| TFNet@224 RGB 零样本（发布权重原配） | 33.92% | 真 artifact，天花板 |
| TFNet@160 RGB 零样本（P156 本实验） | 36.81% | 分辨率代价仅 +2.89pp |
| TFNet@160 RGB 微调（P171） | 39.90% | 比零样本还差 3pp，净负向 |
| VAC@160 RGB 训练（P150） | 53.73% | 骨干差 19.81pp |

- 单组合耗时：224 约 145–274s / 160 约 142–145s（dev 516 条，GPU 推理）。
- 语料级 WER 已在 516 条上聚合，无需逐 epoch 配对；门禁 33.92 复现 +0.00 即证明评估可信。

---

## 诊断（不训练，故无泛化诊断段）

- **分辨率代价温和（+2.89pp）**：与 D3 结论（"160≫224"在我们的训练口径下成立）一致——TFNet 在 160 下几乎无损。
- **通道代价是论文权重的硬伤但不致命**：BGR 比 RGB 差 43.67pp 是"推理时换通道"上界；我们早已修复 R/B 颠倒且数据灰度，训练侧真实损失极小。
- **微调净负向再确认**：P171 微调 best 39.90% 比本实验零样本 160+RGB（36.81%）还差 3pp，且 P171 曲线已恶化到 45%+（见 stage-P171）。⇒ 发布权重的最优用法是**原封不动零样本用 160 输入**，加我们的 word-head 微调反而拖累。

## 配置（完整，便于复现）

```python
# tools/blank_gov/p156_official_ablation.py 0 all
#   加载：Net.moduleNet(1024, 3515+1, "TFNet", cuda, "CE-CSL", True)
#         .load_state_dict(sd["moduleNet_state_dict"], strict=True)
#   推理：model(vid, dl, False) -> out[0]  [T,B,C]（卷积后长度）
#         logp = F.log_softmax(out[0], -1)
#         greedy_decode(logp, dl, idx2word)   # 内部 _conv_len(dl) 算长度，不预截断
#   组合：[(224,True),(160,True),(224,False),(160,False)]
#   评估：official_wer.py 语料级，greedy
```

**修复点（本实验关键）**：首跑 p156 给出 224+RGB=87.93%（门禁红），根因是 `run()` 在传入 `greedy_decode` 前手动 `lp[:_conv_len(dl)]` 预截断，而 `greedy_decode` 内部又对 `dl` 做一次 `_conv_len` ⇒ 双重 `_conv_len` 把解码长度压到 ~1/5，生成率塌到 13%。修正为整段 logits 直接交 `greedy_decode`，与 p78 `_dev_eval`（曾给 33.92/42.47）一致。

## Caveats / 限制

1. **只测零样本（推理时换输入）**：分辨率/通道代价是"不重训"的上界；从头训练会适应，真实损失更小（尤其通道，已修复 + 灰度）。
2. **解码口径**：greedy；官方 42.1% 用 beam width 10，严格不可比（我们锚的是发布权重实测 33.92 而非论文 42.1）。
3. **CSL-Daily 隐患**：权重文件名带 `CSL-Daily`，疑似联合训练；本实验在纯 CE-CSL dev 上复现 33.92，说明对 CE-CSL 有效，但对外宣称前仍需向作者核实。

## Next decision

- **采用**：TFNet@160 RGB **零样本 36.81%** 作为本项目在 CE-CSL 上可达到的最佳可用数字（零训练成本，比 VAC@160 53.73 好 17pp）。
- **不采用**：P171 微调 39.90%（净负向）。
- 若要进一步逼近 33.92，唯一干净路径是 from-scratch 训 TFNet@224（==A 线，但 ~6h/轮，5060 8G 不现实）；否则接受 36.81 为零样本部署上限。
