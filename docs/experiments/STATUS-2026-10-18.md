## 2. 全部实验的结论（按确定性分档）

### 🔴 可判（信号远超噪声）

| 结论 | 证据 |
|---|---|
| **分辨率 160 ≫ 224** | P127：判据区间 mean **+13.29**、224 胜 **0/3**、**SNR 8.54**（本项目最强信号） |
| 224 更差是**过拟合**，非欠训练 | 224 的 train CTC 全程更低（ep15: 13.57 vs 15.10）但 dev 更差 |
| **基线可复现**（换 seed 差 0.32 pp） | P144：配对 mean −0.025、胜率 3/6、SNR 0.016 |
| lr 5e-5 在主配置**有害** | P140：+2.027（0/6）；用 P144 实测噪声 0.838 重算 ⇒ SNR 2.42 |

### 🟡 判死（明确方向，别再投时间）

| 对象 | 结论 |
|---|---|
| 自监督预训练（SimCLR） | 25 轮充分训练后 ΔCohen's d −0.0079、macroAUC +0.0093 ⇒ 双指标都不满足 |
| beam search(10) | 61.86 → **125.58**（输出 +109 %）⇒ 继续 greedy |
| 裁切位置平移 | 官方 center 就是最优（P129 **全量**验证） |
| WER 口径差异 | 语料级 vs 逐句等权只差 0.53 pp |
| weight decay ×10（1e-3） | 有害，是**欠拟合**（Δctc +0.64 → +5.91） |
| lr ×2（2e-4） | 有害，训练不稳定 |
| **model soup** | 平均不同超参的权重 ⇒ 崩溃（生成率 82 % → 19 %） |

### ⚪ 方向可信但幅度不足（< 噪声）

| 对象 | mean | 判定 |
|---|---|---|
| lr 1.5e-4（主配置） | +1.267（0/6） | 更差，不可判 |
| label smoothing β=0.01 | +1.392（1/6） | 更差，不可判 |
| 时序增强 TemporalRescale | −0.724（8/8） | 方向一致但 < 噪声 |
| blank bias 0.75 | −1.09（双 ckpt） | 真实但 < 噪声，**已应用** |

### 🔄 换配置即不复现（**四次**，最重要的教训）

| 效应 | 配置 A | 配置 B |
|---|---|---|
| hflip | fp32+wh0.3：−3.42 | bf16+wh0：**+0.20** |
| bf16 | wh0：−3.75 | wh0.3：**+1.66**（反向） |
| 词级头 | −0.223（SNR 0.14） | — |
| **lr 5e-5** | **wh0/20轮：−2.087（20/20 全胜）** | **主配置：+2.027（0/6）** |

⇒ **「在小配置上搜索、再回代主配置」的策略已被证伪。**

### ✅ 与官方一致（逐项核过源码）

主干初始化（resnet18 pretrained=True）｜归一化（`/127.5 − 1` → [−1,1]）｜

## 3. 诊断发现

### 误差构成（P123 best，全量 dev 515）

| 类型 | 数量 | 占比 |
|---|---|---|
| sub（说错） | 864 | **54.4 %** |
| del（说少） | 685 | **43.2 %** |
| ins（说多） | 38 | 2.4 % |

- 生成率 **77.2 %**（输出 2195 vs 参考 2842）；整句 exact 仅 **1.17 %**
- 🔑 **生成率随句长崩塌**：1-3 → 92.1 % / 4-6 → 80.5 % / 7-9 → 69.3 % / **10+ → 54.7 %**
- ⚠️ 即便 del 全消除，WER 也只降到 ~32 % ⇒ **sub 54 % 才是大头（判别力问题）**

### 过拟合已确认

P123 train CTC 降到 ~5.5 而 dev 仍 55.84 ⇒ 泛化差距。
⚠️ 但加大 wd 证伪（变欠拟合）；label smoothing 也无效 ⇒ **常规抗过拟合手段都没用**。

### lr 的最优值依赖调度长度

| 调度 | 5e-5 | 1e-4 | 更大值 |
|---|---|---|---|
| 20 轮 | **58.30** ✅ | 59.61 | 74.45 (2e-4) ❌ |
| 55 轮 | 57.14 ❌ | **55.84** ✅ | 57.00 (1.5e-4) ❌ |

⇒ 主配置下**官方 lr=1e-4 即最优**；20 轮下"5e-5 更优"无法迁移。

## 4. 方法论资产

| 资产 | 说明 |
|---|---|
| **噪声基准 1.556 pp** | P108 同配置重复实测；P144 补充：换 seed 的配对 std = **0.838** |
| `pair_analyze.py` | epoch 级配对（mean±std + 胜率 + SNR + paired t），禁止只比 best |
| `official_wer.py` | 与论文 Table VIII 算例 **5/5 精确吻合** |
| 早停器 | 三条判据（ep≥MIN + 最近 3 轮全 >3 pp + 发散）⇒ 已自动触发多次 |
| 串行链条 + 崩溃自愈 | 一次只跑一个；崩溃 resume 重启；残file 校验 |
| **已知答案校验** | 诊断脚本必须先复现训练时记录的数字 |

### 关键教训（踩过的坑）

1. **小样本/欠训练不能判方向** —— 自监督 6 轮、P92 只跑 6 轮、P129 冒烟 60 条，三次都给出错误结论
2. **真实测量 ≠ 可用改进** —— 运动重心偏下 29 px 是真的，但平移裁切换不来收益
3. **收据的自动判定字段要对账** —— P92 的 `verdict` 与 `per_epoch` 数据完全相反
4. **跨损失迁移超参要换算** —— CTC 上 label smoothing 的 β 被放大 ~9 倍
5. **WSL 长任务必须用后台任务模式** —— nohup/shell `&` 都会被回收
6. **argparse help 里的 `%` 要写 `%%`** —— 否则运行时才炸

## 5. 诚实处境

**实现层面与评估层面均已逐项核对，10.74 pp 缺口仍未解释。**

已排除：主干、归一化、抽帧、增强链、分辨率（224 更差）、裁切位置、时序增强、
WER 口径、自监督、beam、weight decay、learning rate（两个方向）、label smoothing、model soup。

**剩下的可能（均为推测，依据等级【无】）：**
1. 官方数字可能来自未公开的因素（更多调参、不同数据预处理细节）
2. 硬件/库版本差异（我们 torch 3.14 + torchvision 新版，官方环境未知）
3. 官方未公开的其它实现细节

⚠️ 我们**没有**官方预训练权重（百度网盘，需人工下载）⇒ 无法做"官方 ckpt 在我们 dev 上复现"这一决定性对照。
这是目前唯一能一锤定音回答"到底差多少"的方法。
