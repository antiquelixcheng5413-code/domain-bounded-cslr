# Stage P172：跨分辨率知识蒸馏（CRKD 式）—— 冻结 TFNet@224 教师 → VAC@160 学生

> 关联：P156（零样本代价分解）、P171（全量微调判死）、P150（VAC@160 53.73 基线）
> 日期：2026-10-28
> 方向：用户选定 **B（跨分辨率 KD）**

## 0. 动机（为什么是 B）
- 诊断结论：我们落后 20pp 的唯一主因是**骨干（判别力不足，峰锐度 0.624 vs 官方 0.864）**，不是解码/正则/分辨率。
- P171 证明：全量微调发布权重是净负向（摧毁预训练特征）。
- 免费强教师已就位：发布 TFNet@224 = dev 33.92% / test 33.09%；其在 @160 零样本 = dev 36.81% / test 35.66%。
- 文献对症：CRKD（arXiv:2303.06820）"高分辨率教师→低分辨率学生 + 帧级/分类特征蒸馏"可低分辨率近无损；CLIP-SLA（CVPR2025）证蒸馏优于全量微调。

## 1. 方法（v1 = 响应级蒸馏）
- 教师：发布 TFNet(resnet34MAM 3D)@224 RGB，冻结，按 sid 缓存 logits（p172_teacher_cache.py，RGB_FIX=True+224 同 P156 口径，有效）。
- 学生：VAC(resnet18 2D)@160 RGB（P150 同架构），可训。
- 时间对齐：**实测教师 3D 下采样到 74 帧、学生 2D 下采样到 58 帧，并不天然对齐**；用 F.interpolate(linear) 把教师帧率重采样到学生 58 帧。
- 损失：L = lambda_ctc * CTC + lambda_kd * T^2 * KL(stu_soft || teach_soft)，lambda_ctc=1, lambda_kd=1, T=4，blank=0（师生一致）。

## 2. 写死判据（启动前）
- 成功线：dev < 36.81%（教师160零样本）。强成功：逼近 33.92%。
- 相对 from-scratch：必须比 VAC@160 53.73% 低 >= 2pp 且配对胜率 >= 75%。

## 3. 运行结果与结论（2026-10-28，判定：负向/判死）
- 训练因 **CUDA error 999（sticky）在 ep05 首步 CTC 崩**，仅跑到 ep04（已无残留进程，GPU 已自愈，重启可行）。
- best ckpt：artifacts/checkpoints/p172-distill-best.pt（ep04, **dev=77.55%**）。
- 早期轨迹 vs P150（纯 VAC 无 KD）：

  | epoch | P150(无KD) | P172(KD lambda=1) | 差 |
  |---|---|---|---|
  | ep1 | 81.56 | 79.77 | -1.79 |
  | ep2 | 78.96 | 79.63 | +0.67 |
  | ep3 | 77.30 | 79.56 | +2.26 |
  | ep4 | 75.55 | 77.55 | **+2.00** |

  P172 在 ep4 比 P150 **高 2pp**，且 4 轮仅降 2.2pp（P150 降 6pp）→ 蒸馏略**有害**、学得 slower。

- **根因（结构性，非偶然）**：
  1. KD 项量极小：loss_kd 约等于 0.9 vs loss_ctc 约等于 30，KD 仅占梯度约 3%，即使完美对齐也**不可能**把 WER 拉低 >= 2pp（判据无法满足）。
  2. 跨骨架+跨帧率响应级蒸馏不匹配：教师 3D@224@74fr、学生 2D@160@58fr，逐帧 softmax 对齐与 CTC 的 blank/对齐需求相冲突，故略有害而非有益。
  3. TFNet 自家内部 KD 用 25*kld 且师生**同架构同帧率**才有效；本设置不满足该前提。

- **判定**：P172 v1 不可能满足写死判据（dev<36.81 或比 53.73 低>=2pp）。**判死。**
- 真天花板仍是发布权重零样本：dev 33.92 / test 35.66（@160 RGB，零训练成本，比 VAC@160 53.73 好约 18pp）。
- 注：v2 帧级特征蒸馏理论上可强化，但跨骨架/帧率响应级已证不匹配，且 55 轮约 23h 成本高危；不优先。
