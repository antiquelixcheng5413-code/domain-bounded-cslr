## Research question

岔路 B（帧级特征 → LLM 组句）值得做吗？B2 探针只回答其中一个子问题：

> 官方 `resnet34MAM` 导出的帧级中间层特征，是否携带足够的**词级判别信息**？

注意：这测的是**前端**，**不回答** LLM 后端能否降低 WER。

## 🔴 原判据失效：macroAUC 在全类上不可计算

这不是调参问题，是**数据本身的算术事实**：

| 项 | 值 |
|---|---|
| 片段总数 | 28,272 |
| distinct 类 | **3,841** |
| **测试侧样本数为 0 的类** | **1,281（33.3 %）** |
| 测试侧 ≥2 样本的类 | **1,214 / 3,841** |

⇒ 三分之一以上的类在测试侧无从评估，`roc_auc_score` 报
`UndefinedMetricWarning: Only one class is present in y_true`，最终返回 **nan**。

⇒ **实验启动前设定的判据（macroAUC ≥ 0.25 判活）在本数据规模下不成立。**
这是「判据本身不可行」，与「为了得到好结果而改判据」不同——前者必须修正，后者禁止。

### 修正方案

| 指标 | 适用范围 | 角色 |
|---|---|---|
| **Cohen's d** | 全类（1948 个 ≥2 样本的类） | **主判据**——零号自检，不依赖分类器，本就已写入脚本 |
| macroAUC | 高频类子集（训练频次 ≥ 20 ⇒ 165 类，覆盖 62.9 % 片段） | 辅助验证 |

---

## 核心结果一：Cohen's d = +0.4119

同 gloss 内部距离 vs 异 gloss 距离的标准化效应量：

| 特征 / 视图 | Cohen's d | 来源 |
|---|---|---|
| **resnet34MAM RGB 帧特征（本实验）** | **+0.4119** | P107 |
| upper pose+face（56 维） | +0.3041 | P36 |
| rgb（CLIP 逐帧 512） | +0.1006 | P36 |
| full368 | +0.0410 | P36 |
| hands [0:126]（占 68 %） | **−0.0171** | P36 |

⇒ **+0.4119 高于 P36 记录的全部 landmark 视图。**
（两次独立运行分别得 +0.4112 与 +0.4119，差 0.0007，可复现。）

⚠️ **但不可直接宣称「RGB 优于 landmark」——两者模态不同**，此处只能做效应量量级参照。

---

## 核心结果二：高频类子集 macroAUC = 0.5628

在**频次 ≥ 20 的高频类子集**上（17780 片段 / 165 类），进一步剔除「测试侧 <2 样本或训练侧缺失」的类后剩余 **163 类**，逻辑回归（PCA 256 维）得到：

| 指标 | 值 | 参照 |
|---|---|---|
| **subset macroAUC** | **0.5628** | 163 类多分类随机基线 = **0.5** |
| fit 耗时 | 226 s | — |

⇒ 高于随机基线 **+0.063**。

**为什么还必须做这一步过滤**：即使限制到高频类，直接跑仍返回 nan。原因是仍有 2 个类不满足「训练侧 ≥1 且测试侧 ≥2」，它们在 `y_true` 的列只有单一取值，per-class AUC 无定义，进而让 macro 平均变成 nan。

**判读须谨慎**：

- 随机基线是 **0.5 而非 0**，所以实验前写死的阈值 `AUC ≥ 0.25 判活` **阈值过松**——它低于随机水平的一半，任何合理的特征都能通过。
- ⇒ **本报告中该判定不作为主要依据**，主要依据仍是 Cohen's d。
- 0.5628 相对 0.5 的增益（+0.063）**远不如** Cohen's d 所显示的效应量那么强。
- ⚠️ 与 P36 的 `full368 macroAUC = 0.6091` **不可直接比较**——后者只有 150 类，类别越少该指标越容易偏高。

---

## 该结果能说明什么、不能说明什么

**✅ 能说明**：官方 resnet34MAM 第 4 层输出经片段池化后，**确实携带可测量的词级判别信息**，且效应量不弱。岔路 B 的**信息供给端是成立的**。

**❌ 不能说明**：LLM 后端能否把这个信息转成更低的 WER。

这与 `stage-...`（P109 理论评估）**不冲突**——那次评估的三个错配全部落在**后端**：

1. 数据密度低 8.7 倍（7.4 vs 59.9 / 64.4 token/词）⇒ 影响 LLM 训练，不影响特征提取
2. 输出 gloss 而非自然语言文本 ⇒ 语言先验错配
3. WER 惩罚幻觉 vs BLEU 容忍幻觉

⇒ **前端没问题，风险仍在后端。**

---

## Caveats

1. **模态不同**：Cohen's d = +0.4112 在 RGB 帧特征上；P36 参照值是 landmark。跨模态只比效应量级。
2. **probe 而非端到端**：探针用逻辑回归 + 片段池化，不是最终的 CTC 或 LLM 链路。
3. **进程保活**：B1 脚本用 `nohup setsid & disown` 挂起时两次静默死亡（一次活 6 h 错过收据，一次活 60 s）。
   已确认**非 OOM**（5.6 Gi 可用、dmesg 无记录）、**非语法错误**。改用后台任务模式后正常。
   另修复 `p107_branch_b.py:65` 字段名 bug（`ckpt_wer` → `best_wer_official`）及 `fit()` 传 one-hot 的 bug。

## Next decision

两个独立指标**同向支持**：帧级特征携带词级判别信息（Cohen's d +0.4119、subset macroAUC 0.5628）。

但这**不等于岔路 B 值得做**。探针只测前端——P109 理论评估列出的三条错配全部落在**后端**，本次结果一条都没有触及：

1. 数据密度低 8.7 倍（7.4 vs 59.9 / 64.4 token/词）⇒ 影响 LLM 训练，不影响特征提取
2. 输出 gloss 而非自然语言文本 ⇒ 预训练语言先验错配
3. WER 惩罚幻觉 vs BLEU 容忍幻觉

⇒ 要回答「岔路 B 是否值得做」必须有端到端实验，而那受 **8 GB 显存预算**约束（论文用 4×V100 / 128 GB）。

**待办（按优先级）：**

1. 补 `word_head=0.0 + warmup_ep=3` 解混淆实验（P101 遗留，**最高优先级**——不解决则「词级头有效」不能写死）
2. 若仍要推进岔路 B：**先做 0.5B 级小 LLM 可行性验证**，不做全量 Qwen 微调
3. **修正判据设计教训**：`macroAUC ≥ 0.25 判活` 阈值有误——多分类 AUC 的随机基线是 **0.5**，
   阈值却低于随机基线的一半，等于几乎必然通过。今后凡 class-averaged 指标，
   阈值必须设在**随机基线之上**，并先验算可计算性。
