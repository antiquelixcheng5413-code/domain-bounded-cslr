# 阶段报告：P133 / P134 —— 误差构成诊断与 blank 偏置

- **日期**：2026-10-14
- **回答的问题**：下一步该试什么？——先弄清误差是"说太少 / 说太多 / 说错了"
- **结论**：
  1. 误差以 **sub 54.4% + del 43.2%** 为主，ins 仅 2.4%；**生成率只有 77.2%**
  2. **生成率随句长急剧下降**（10+ token 的句子只输出 54.7%）
  3. 抑制 blank 能改善，但**两个 checkpoint 交叉验证只有 ~1 pp**（55.84→54.75 / 59.61→58.80）
  4. ⇒ 欠生成**只能解释一小部分**，大头仍是判别力问题

## 1. P133：误差构成（P123 best ep39，全量 dev 515）

| 误差类型 | 数量 | 占编辑数 |
|---|---|---|
| 替换 **sub**（说错） | 864 | **54.4 %** |
| 漏词 **del**（说少） | 685 | **43.2 %** |
| 多说 **ins**（说多） | 38 | **2.4 %** |
| 合计 | 1587 | ✅ 与 `official_wer` 的 edits 完全一致 |

```
参考 token 总数 : 2842
输出 token 总数 : 2195
生成率          : 77.2 %        ← 输出只有参考的 3/4
整句完全一致    : 6 / 515 = 1.17 %
```

### 🔑 关键模式：生成率随句长崩塌

| 参考句长 | 句数 | sub | del | ins | 生成率 | 该桶 WER |
|---|---|---|---|---|---|---|
| 1–3 | 13 | 16 | 4 | 1 | **92.1 %** | 55.26 % |
| 4–6 | 401 | 645 | 432 | 35 | **80.5 %** | 54.64 % |
| 7–9 | 94 | 188 | 215 | 2 | **69.3 %** | 58.36 % |
| 10+ | 7 | 15 | 34 | 0 | **54.7 %** | 65.33 % |

⇒ 句子越长，模型输出得越少。**CTC 在不确定时退化为输出 blank**，长句尤其严重。
⇒ 但即便把 del 全部消除，WER 也只降到 ~32 % ⇒ **欠生成不是全部答案**。

## 2. P134：blank 负偏置（零训练成本对策）

做法：解码前对 blank 类（index 0）的 logit 减常数 `bias` ⇒ 抑制 blank ⇒ 迫使多输出。
（与 beam 不同：beam(10) 曾让输出 **+109 %** 到失控（P120）；bias 是温和连续可调的。）

### P123（best 55.84）

| bias | WER | 生成率 | Δ |
|---|---|---|---|
| 0.00 | 55.84 % | 77.2 % | — |
| 0.25 | 55.49 % | 79.0 % | −0.35 |
| 0.50 | 54.96 % | 81.4 % | −0.88 |
| **0.75** | **54.75 %** | 83.6 % | **−1.09** |
| 1.00 | 54.93 % | 85.9 % | −0.91 |
| 1.50 | 55.28 % | 89.4 % | −0.56 |
| 2.00 | 56.02 % | 93.5 % | +0.18 |
| 3.00 | 58.55 % | 100.8 % | +2.71 |

### 交叉验证：P124e（完全不同的 checkpoint：wh0 / 20 轮 / 无补帧）

| bias | WER | 生成率 | Δ |
|---|---|---|---|
| 0.00 | 59.61 % | 70.8 % | — |
| 0.50 | 59.01 % | 77.6 % | −0.60 |
| 0.75 | 58.87 % | 80.7 % | −0.74 |
| **1.00** | **58.80 %** | 83.6 % | **−0.81** |
| 1.50 | 59.96 % | 89.7 % | +0.35 |
| 3.00 | 65.20 % | 105.0 % | +5.59 |

- 🔑 两者的 **bias=0 都精确复现各自收据值**（55.84 / 59.61）
- 🔑 曲线**同为平滑 U 形**，最优区间**同为 0.75–1.0**
- 🔑 改善幅度 −1.09 / −0.81 pp（接近）
⇒ **效应真实且可复现，不是单 checkpoint 的巧合**

⚠️ **但幅度约 1 pp，低于噪声 1.556 pp** ⇒ 按判据属"弱证据"，**不判活**。
⚠️ 且 bias 是在 dev 上扫出来的，存在"在 dev 上选超参"的乐观风险
（两个 ckpt 一致降低了这个风险，但不能完全排除）。

## 3. 所以"下一步试什么"

### 已排除（不要再投时间）

| 方向 | 结论 |
|---|---|
| 主干 / 归一化 / 抽帧 / 增强链 | 与官方一致 |
| 分辨率 / 裁切位置 / 时序增强 | 官方选择更好或差异不可判 |
| WER 口径 | 差 0.53 pp，不是缺口来源 |
| 自监督预训练 | 判死 |
| beam search | 判死（+109 % 输出） |
| hflip / bf16 / 词级头 | 换配置即不复现 |

### 剩余选项（按性价比排序）

| # | 方向 | 成本 | 期望收益 | 依据 |
|---|---|---|---|---|
| 1 | **应用 blank bias ≈ 0.75–1.0** | **零** | **~1 pp** | 【有】双 ckpt 交叉验证 |
| 2 | **换 seed 跑 2 次** | ~18 h | 0（只测方差） | 【有】回答"55.84 是均值还是运气差" |
| 3 | 跑满 55 轮 | ~11 h | 低 | 【有】P123 在 ep39 触底、ep48 平台 |
| 4 | 架构升级 TFNet | 10 h+ | ≤3 pp | 【有】官方 VAC→TFNet 3.0 pp |

⚠️ **一条必须说清的判断**：
架构升级（#4）**不解决根本问题**。官方 VAC→TFNet 只值 3.0 pp，而我们
距官方 **VAC** 就差 10.74 pp ⇒ 问题不是"VAC 架构上限低"，而是
**我们跑不出官方 VAC 的水平**。换架构只会把同样的差距平移过去。

⇒ 真正能回答"我们是不是真的差"的只有 **#2（换 seed 看方差）**：
若 2–3 个 seed 都在 55–56 %，说明 55.84 是稳定的，那么官方 45.1 很可能
来自多次运行取优或未公开的因素；若方差很大（53–58 %），则说明我们只是运气差。

## 4. 教训

| # | 教训 |
|---|---|
| 1 | **先分解误差再选方向**：sub/del/ins 的构成决定了完全不同的对策 |
| 2 | 生成率随句长崩塌是 CTC 的典型退化，看总量会漏掉这个模式 |
| 3 | 单 checkpoint 的结论要**交叉验证**；本次两个 ckpt 一致才敢说效应真实 |
| 4 | 🔴 **补帧设置要从 ckpt config 读，不能硬编码**：我第一版写死 `OFFICIAL_PAD=True`，
  导致 P124e（无补帧）的 data_len 算错；修正后 bias=0 才精确复现 59.61 |
| 5 | 零成本收益（1 pp）虽小，但值得拿——前提是确认它不是 dev 过拟合 |
