## 2. 单变量设计

复用 E1 已三层审计验证的 `GlossPrototypeBank + FeatureCapture`（hook 只取 `classifier11` 第一次调用），
**唯一改动**：负类从「后验最高的非目标类」换成 P222 混淆表里该 gloss 的真实混淆类，
不足 `n_neg=16` 时才用原后验策略补齐。

- 梯度自检（11:16）：G1 `n_conf_used=28/2`、loss 2.9786、feat 梯度非零、proto 单位范数；
  `conf_map=None` 时 `n_conf_used=0` ⇒ **严格保持 E1 原行为**，默认开关不改任何已有实验。
- 冒烟（11:17）：`G1 confusion map: 3436 gloss / 17054 pairs` 生效，1 轮完成、无 NaN。
- 配方逐项沿用 P184：160 / 冻结 conv2d / lr 2e-5 / wd 1e-4 / batch 2 / bf16 /
  seed 42 / 6 轮 / `p184-init-tfnet160.pt`；`--csgc-weight 0.3`（与 E1 相同）。
- 训练期-only，推理零开销。

## 3. 判据（统一 R1–R8，全部满足才 PASS）

主看尾部（D4 教训）：

| 编号 | 规则 |
|---|---|
| R1 | uWER 改善 ≥ 2.0pp |
| R2 | 低频桶 WER 改善 ≥ 2.0pp |
| R3 | 高频桶恶化 ≤ 1.0pp |
| R4 | WER_official 退化 ≤ 1.0pp |
| R5 | 插入数相对基线增幅 ≤ 10%（E0 教训） |
| R6 | micro sub+del 恶化 ≤ 0.30pp（D4 教训） |
| R7 | 6 轮 best dev ≤ 34.80 |
| **R8** | **低频桶单独配对 bootstrap（句子级 20000 次）95% CI 下界 > 0** |

R8 是本轮新增、方案 `OPT-DIRECTIONS-3` 明确要求的护栏：低频桶只有 692 token，
不能套 ±0.77pp 总量噪声地板。为此 `night_eval_full.py` 在 `per_item` 里增 `low_n/low_err`，
`night_judge.py` 增 R8；两个工具向后兼容（旧收据无 `low_n` 时不启用 R8）。

## 4. 评估流程（训练结束后自动执行）

1. 用**新版** `night_eval_full.py` 重算 `p184-base`（旧基线收据无 `low_n`，必须重算才能启用 R8）
2. 评估 `p223-g1-best.pt` → `p223-g1-uwer.json`
3. `night_judge.py --kind train` 按 R1–R8 判定，出 `p223-g1-judge.json`
4. `night_report.py` 出阶段报告（WSL 主副本 + 桌面镜像）
5. 判定写入日志与项目记忆

## 5. 判定含义与红线

- **PASS** 只代表「值得投 2 seed(42/43) + 配对 bootstrap 复跑」，**不等于性能已确认提升**，
  也不进 test。test 冻结，只在复跑过线后一次性终评。
- **FAIL** ⇒ 不进复跑、不跑 test、不调参重跑；结论并入汇总。
- 单次 6 轮只作筛选；落进 dev 噪声地板的信号一律判「无差别」。
- 混淆表来自 train；**dev 混淆表只用于先验诊断，不得进训练**（P219/P220/P221 是诊断产物）。
- 未跑 test、未 commit、未 push。
