## 2. ✅ 已应用且有效（12 项）

### 2.1 🔴 CTC target 索引 +1 修复 — **最关键的单点改动**
- **论文依据**：无（工程 bug，但影响所有下游结论）
- **实测**：dev 严格 WER **0.976 → 0.702**；8 条真实样本解码 **0/8 → 8/8**
- **原理**：CTC 类 0 是 blank，`collate_samples` 把 0-based 词表索引直接当 target，
  整体错一格，`<unk>` 被当成 blank
- **影响**：P0–P22 的所有 WER 结论作废
- 收据：`p23-off-by-one.json`

### 2.2 扩词表 300 → 3516 ⏳→ 进行中
- **论文依据**：CE-CSL 官方论文报告 **词表 3515 / Dev OOV = 0**
- **实测**（P62b，库口径）：3516 词表下 dev unk **0.0%**、整句可表达 **100%**
- **可行性**（P59b）：峰值内存 **64.8 MB**、参数 3.07M → 3.89M、**更快**
- **CTC 约束**（P63b）：dev 最长句 13 → 需 T ≥ 25 < 48，**无冲突**
- 收据：`p58/p59/p59b/p62b/p63b`

### 2.3 landmark-only 路线（vs 官方 RGB 路线）
- **论文依据**：官方 6 个模型**全部用 RGB**，landmark 路线**无文献对照**
- **实测**：lm_only **0.5211** < rgb+lm 0.5314 < rgb_only 0.6949
- **意义**：这是本 FYP 的**立足点** —— landmark vs RGB 在同一数据集的系统对比
- 收据：`p40-full.json`、`p42-lm-final.json`

### 2.4 upper 块（pose+face）与 body_deltas 的判别力
- **论文依据**：ST-GCN（ref11）批评"只用关节坐标、不建模空间关系"
- **实测**（Cohen d，片段池化）：**body_deltas +0.4796 全场最高**；upper +0.3041
  vs hands +0.0723
- **意义**：指明特征该往哪块加权 —— **motion 段比静态点更有信息**
- 收据：`p37-upper-block.json`、`p38-verify-upper-deltas.json`

### 2.5 推理提速 17.8s → 4.2s（4.2x）
- **论文依据**：无
- **实测**：同帧内三模型并行，**逐位一致**（`np.array_equal == True`）
- **被否决的方案**（均有数据）：GPU delegate 慢 50–100x（WSL 走 llvmpipe 软件渲染）、
  降分辨率无效（MediaPipe 内部固定 192×192）、抽帧破坏 VIDEO 跟踪链（cos 0.81）
- 收据：`p43-speed-bugs.json`

### 2.6 指标口径审计（四件套）
- **实测差异**：折叠口径 0.5211 / 剔 unk 0.7919 / 逐句等权 **2.8774** / exact 3.5%
- **机制**：OOV 折叠成 `tokens[0]`（`<unk>` 本身可预测），实测**送分 0.1755**，
  参考里 738 个 unk 模型对上 554 个（**命中率 75.1%**）
- **验证**：穷举法 / 手写 DP / **jiwer** 三方一致 → 算法无误，**问题在报告口径**
- 收据：`p44-wer-audit.json`、`p50*.json`

### 2.7 signer 重叠核查
- **实测**：train/dev **12 个 signer 100% 重叠**，514/514 样本 signer 都见过
- **意义**：**排除**了"跨 signer 泛化"这个常见猜测；dev 是同 signer 条件
- 收据：`p45b-signer-overlap.json`

### 2.8 8 条样本过拟合 + 词级线性探针（定位瓶颈的关键证据）
- **实测**：全新模型可过拟合到 WER **0.0000**（容量与目标无损）；
  词级线性探针 **macroAUC 0.7222**（随机 0.0213）
- **意义**：**特征里有词身份信息**，问题不在"学不动"
- 收据：`p47c-root-cause-test.json`

| 方法 | 论文依据 | 实测结果 | 失败机制 |
|---|---|---|---|
| **加训练轮数 30→150** | — | dev 只动 **−0.0063**，gap 扩到 0.38 | 已收敛，纯过拟合 |
| **ST-GCN 骨架拓扑** | ref11 ST-GCN | train 完美(dev 0.0092) 但 dev **0.6938**；加拓扑 22.24M → dev 0.7311 | 拓扑有用但**加速记忆**，不是泛化瓶颈 |

| **受控解码（词频先验）** | ref07/ref15 用 CTC+beam+词表约束 | 剔 unk WER **0.7919 → 0.8171/0.8452/0.8710 单调变差**；前5词占比几乎不动 | **正确词根本没进前几名**（top-1 仅 10.6%、top-5 44.8%），重排无从下手 |

### ⚠️ 词频校准失效的机制（P47b，值得记住）
- 87.4% 的帧 argmax 是 blank，平均 blank 概率 **−2.205**
- `。` 的平均 log-prob **−50.97**，而全部非 blank 类约 **−7.8**
- ⇒ **不是高频词分数高，是其它词分数更低**。减 log P 只会把随机词推上来。

## 5. ⚠️ 作废的实验（设计有缺陷，结论不可用）

| 编号 | 问题 | 影响 |
|---|---|---|
| **P6 词表消融** | `patience=8` 而三组"最佳"都在 **ep2~ep4** → early-stop 伪造；且跑在 off-by-one 修复前 | 「词表裁剪影响有限」结论**无效** |
| **P19/P31/P34 探针** | 用**整句池化**成 1 个向量，让句内 3.77 个 gloss 共享它去查询 → 任务本身不可解 | 0.0762/0.0098/0.0028~0.0063 全部作废 |

### 新增铁律
> **消融实验若"最佳 epoch" < patience，说明 early-stop 提前触发，该实验所有配置结论作废。**
>
> **判别力探针必须用片段池化**（按 gloss 数等分时间轴，每段对应 1 个 gloss），
> 绝不能用整句池化。

## 9. 指标口径铁律（P50，违反即误导）

**报 WER 必须四件套**：

| 口径 | 值 | 含义 |
|---|---|---|
| token 级 WER | 0.5211 | 工程指标，但被 unk 送分美化 |
| **剔 unk WER** | **0.7919** | **模型对已学词的真实准确率** |
| **逐句等权 WER** | **2.8774** | **最接近"看一条视频"的直觉** |
| **exact 率** | **3.5%** | 完全正确的句子比例 |

**折叠送分机制**：`index_of()` 对 OOV 返回 0，而 `tokens[0]` 就是 `<unk>`，
所以 OOV 折叠成了**模型可主动预测的真实类**，实测命中率 75.1%。

**反事实**：把参考里的 `<unk>` 全删掉再算 WER → **0.7919**。
⇒ 0.5211 给人偏乐观的印象。

## 10. 审计铁律（今天三次栽在同一类错误上）

**必须 import 库函数，禁止自己写"看起来等价"的简化版本**：

| 次数 | 我自己写了什么 | 后果 |
|---|---|---|
| P44 | 自己构造 WER 参考 | 数字差 **2.5 倍** |
| P57/P58 | 自己写 `g.split('/')` | 覆盖率全错（报 6.2%，实际 **0%**）|
| P61/P63 | 按**位置**解读 presence 数组 | 把 pose 当 handL，误判检出率 |

**根因**：简化实现/位置解读都会漏掉库里的语义约定。

**⇒ 铁律**
1. 覆盖率 / WER / 频次统计 → 直接 `import` 库函数
2. 多维数组 → 按**语义名称**解读，不按位置下标
3. 写任何特征提取器前 → 先读**训练特征的构造代码**，逐块核对语义顺序
4. 出现"自相矛盾的数字" → 先怀疑索引空间/样例设计/口径，再怀疑算法
