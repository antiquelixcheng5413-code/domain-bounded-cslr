## 1. 设计（与「再加轻量损失项」彻底不同的范式）

- **记忆库（只来自 train）**：对每条 train 视频做一次前向，取 `classifier11` 输入特征
  `[T,1024]`（E1 的 FeatureCapture 已验证），按 CTC greedy 路径切成连续相同非 blank 段，
  每段取帧特征均值 + L2 归一化，得到「段级实例 → gloss」条目。
  预计 ~27k 条 × 1024 维；PCA128 + fp16 后约 7MB。
- **推理期融合（RAC 分布插值）**：dev 每句同样切段，每段用其特征在 train 库里检索 top-K，
  按邻居 gloss 的相似度加权投票得 `P_knn[C]`；对段内每一帧做
  `lp = log( (1−λ)·exp(lp) + λ·P_knn )`，再 greedy 解码。
  主干、适配器、分类头**全部不动**，不花 6 轮训练预算。
- dev 后验复用已落盘 `p188_logp_p184.pt`；只需新导出 dev 段特征。
- **硬约束**：库只由 train 构建，dev/test 样本不得回流；段标签来自模型自身 greedy 路径
  （无外部帧级标注），与 `p222_confusion_map.json` 一样是 train 来源。

## 2. 固定参数（启动前写死）

| 项 | 值 |
|---|---|
| 特征源 | `classifier11` 第一次 hook 输入，段均值 + L2 归一化 |
| PCA 维度 | 128（只在 train 库上 fit） |
| 检索 K | 32 |
| 距离 | cosine |
| λ 网格 | 0.0 / 0.05 / 0.10 / 0.20 / 0.30 / 0.50 |
| 段切分 | baseline greedy 路径（不迭代重切，第一版固定） |
| 模型 | `p184-tfnet-freeze-best.pt`（与所有 dev 基线同口径） |

**λ 选择规则（防 p-hacking）**：在满足护栏 R3/R4/R5/R6 的组合中取 **uWER 最低**者作为唯一代表；
若无组合过护栏，代表 = λ=0（基线，自动判负）。全网格另存 json。

## 3. 判据（统一 R1–R8，全部满足才 PASS）

| 编号 | 规则 |
|---|---|
| R1 | uWER 改善 ≥ 2.0pp |
| R2 | 低频桶 WER 改善 ≥ 2.0pp |
| R3 | 高频桶恶化 ≤ 1.0pp |
| R4 | WER_official 退化 ≤ 1.0pp |
| R5 | 插入数相对基线增幅 ≤ 10% |

另报：记忆库条目数 / 大小、单次 kNN 查询延迟、λ 敏感性曲线、覆盖 dev 段的比例。

## 4. 判定含义与红线

- PASS 只代表「值得投 2 seed + 配对 bootstrap 复跑」，**不等于性能已确认提升、不进 test**。
- FAIL ⇒ 不调 λ、不换 K 重跑、不进 test；结论并入汇总。
- λ 网格在 dev 上选参有过拟合风险，护栏优先 + 预注册选择规则只能降低、不能消除。

  **不改变任何判据或参数**。
