## 0. 一句话结论

前五轮 14 连败之后，问题不是「试得不够多」，而是所有实验共享同一个框架：
**在固定的 4973 条真实句子上，只改损失 / 后验 / 输入 / 参数**。
真正没碰过的自由度是 **训练数据的组织方式本身** ——
用 CTC 强制对齐把 train 视频切成 per-gloss 片段，再合成**全新的合法训练句子**。
它不违反「不混用数据集 / 不新增标注」红线，架构无关，直接打 48% 单样本类的根本瓶颈。
零成本诊断 **J1 已过线**（片段可切）。这是本项目第一条「改数据而非改模型」的路。

## 1. 为什么「再找一条类似的路」没有意义（共同根因）

| 轮次 | 改的是什么 | 结果 |
|---|---|---|
| 一（P171–P206） | 微调 / 蒸馏 / 换主干 / 通用增广 / 解码 / 集成 | 全负向或不显著 |
| 二（D1–D4） | 解码重排 / 一致性正则 / 帧级监督探针 / 类别重加权 | 全判负 |
| 三（E0–G1） | 先验校正 / 原型对比 / 视觉-文本对齐 / 真实混淆 hard negatives | 全判负 |
| 四（H1 / H2-a） | 外部记忆检索 / 参数自适应 TTA 前提 | H1 判负；H2-a 机械 PASS 但机制不支持 |
| 五（I0 / I1） | 输入时间分辨率 / 对齐密度 | 两侧都恶化，当前帧密度是局部最优 |

**共同点**：训练语料始终是同一批 4973 条真实句子，标签分布固定
（3515 类 / 28272 token / **48% 类只有 1 个样本** / 90.4% 类 ≤10）。
所有「改损失/改后验/改输入」的方法都在这个固定的、极端长尾的样本集上做重分配：
D4 把错误从低频搬到高频、E1/G1 是类别间重分配、I0 把模型推出训练分布。
**没有任何实验增加过"尾部 gloss 出现在新上下文里"这件事** —— 这正是第六轮的立足点。

## 2. 三条真正跳出框架的候选

### K1. CTC 强制对齐 → gloss 片段库 → 合成新训练语料（优先级 1，主推）

- **机制**：从 train 视频里切出每个 gloss 的连续帧区间（含 co-articulation 过渡），
  建立「gloss → 多个视觉实例」的片段库；用本地 LLM 生成**新的合法 gloss 句子**
  （词表约束、低频优先、排除与 dev/test 序列重复）；按句逐词随机取实例直接拼接成新 RGB 视频，
  标签是新句。训练时按固定比例混入。**改的是数据分布，不是模型。**
- **依据**
  - 【有】**arXiv:2606.11925**（Robotka et al., 2026-06）：完全同款流水线
    （CTC forced alignment → per-gloss clips → LLM 生成新句 → 随机拼接），
    Phoenix-2014T **+2.92 BLEU-4**；且「真实数据双倍采样」只有 21.17 vs 基线 21.38，
    证明增益来自合成内容而非多走梯度步。代码 `github.com/robizso/slt-datagen`。
  - 【有】**ACM MM 2020《Boosting CSLR via Cross Modality Augmentation》**（arXiv:2010.05264）：
    **CSLR 任务本身**用对齐切段 + 替换/插入/删除编辑生成伪视频-文本对，
    配 CTC + 判别损失 + 跨模态语义损失；明确写「增广样本不再与原样本共享语义」。
  - 【有】**EMNLP 2024 / arXiv:2401.05336《Towards Online CSLR》**：
    CTC 强制对齐做 sign segmentor，人工评估 **93.4%** 分割准确率；
    据此建孤立手势词典 + 滑窗 ISLR + saliency loss，CSL-Daily 16 帧窗口 WER 29.3%
    （直接套用离线模型 103.3%）；在线模型特征经轻量 adapter 反哺离线模型，
    Phoenix14 / Phoenix14T / CSL-Daily test **+0.8 / +0.7 / +0.9pp**。
  - 【有】**arXiv:2506.09643**：stitched skeleton 预训练让 PHOENIX14T BLEU-1 32.41→38.61。
  - 【有】本地 **J1 前提诊断**（见 §3）：99.26% 的 gloss 可切出 ≥8 输入帧的连续区间。
  - 【间接】FGXM (PRL 2025) 的 uWER 与低频实词诊断、CSGC (AAAI24) 的跨句一致性。
- **⚠️ 必须计入的反证据（文献自己的消融）**
  1. **「只重组视觉片段、不换句子」比基线更差**：去掉 LLM 生成后 BLEU-4 21.38 → **20.04（−1.34）**。
     ⇒ 收益主要来自**新的 gloss 组合（语言多样性）**，不是「多造视觉样本」。
     K1 因此**必须**配 LLM 生成新句，不能做成简单的同类片段重采样。
  2. **合成数据用于预训练有害**（VLP 阶段 BLEU-4 ≈19 → ≈11）；只应用于下游微调
     ⇒ 我们正好是 PEFT 微调，符合。
  3. **L2 过渡平滑是负收益**（−0.93 / −1.06 BLEU-4）⇒ 直接拼接，不做边界优化。
  4. **最大机制风险**：上述收益全部在 **SLT（BLEU/ROUGE）** 上测得，
     而我们是 **CTC gloss 识别**，CTC 的条件独立假设不建模句法依赖
     ⇒ 「新上下文」的收益机制在 CSLR 上可能大幅打折。检索明确承认：
     **没有**任何论文在 CSLR 上以 tail-class / macro-F1 报告该路线的效果。
  5. **边界偏差自我强化**：文献承认「用同一模型既切分又训练会放大边界误差」。
     我们计划用 P184 切分 + 继续 P184 PEFT，正是这种情形 ⇒ 必须作为风险写入预注册。
- **本地工程基础已齐备**：`p222_g0_train_confusion.py`（train 全量前向 + 分片断点 + 自动重试）、
  `p224_train_segments.pkl`（H1 已建的 28010 条 train 段实例，可作为特征级片段库备选）、
  本地 Qwen2.5-1.5B 文本模型、3516 词表、P219 的严格 Levenshtein 回溯。
- **成本**：切片段 train 全量前向 ~30–40 min GPU（非训练）→ 生成句子 ~10 min CPU
  → 合成 ~20 min CPU/IO → 6 轮 PEFT ~3 h GPU ≈ **半天**。
- **判据（须另写预注册，启动前固定）**：统一 R1–R8（主看 uWER / 低频桶）+ 新增
  「合成句与 dev/test 无 gloss 级精确重复」泄漏检查；合成比例、生成句数、随机种子、
  混合比例全部写死。PASS 只代表值得 2 seed 复跑，不进 test。

### K2. 换辅助任务：孤立手势词典 + 轻量 adapter 反哺（优先级 2）

- 【有】arXiv:2401.05336：在线 ISLR 特征经 adapter 增强离线模型，三个数据集 +0.7~0.9pp；
  CSL-Daily 是中文、词表 2000（我们 3516，长尾更长）。
- **与已判死项的区别**：P198 / P200 是随机初始化 Conformer 换时序模块（6 轮拟合失败）；
  K2 是**用独立的孤立手势分类任务**训练判别器，提供与 CTC 互补的监督信号。
- **反证据**：仍需新模块 + 训练，P200 已证 6 轮内随机初始化大模块拟合失败；
  且需要 K1 的片段库作为前置 ⇒ 成本高、与 K1 强耦合。
- ⇒ 仅在 K1 判负、且用户愿意再投约一天时考虑；不作为下一轮首选。

### K3. 选择性预测 / 拒识（改变交付形态，不追 WER）—— **已被 J2 判 STOP**

- 【有】Chow (1970)、El-Yaniv & Wiener (2010)、Geifman & El-Yaniv (2019) 的
  selective classification / risk-coverage；【有】conformal abstention（arXiv:2604.13254）
  在 80% coverage 下把错误率 18.7%→10.9%；【无】CSLR 领域无先例。
- **J2 实测**：句子级置信度（逐帧 max log-prob 均值）与句子 WER 的
  **ρ = −0.4924**（判别力明确），但 70% coverage 下 WER 34.06%→28.69%，
  **相对降 15.75% < 25% 判据线** ⇒ 按写死规则 `STOP`，不投入。
- 诚实说明：置信度有判别力，可作为错误分析副产品，但不构成可用的覆盖率-风险权衡。
  且它**不提升 WER**，是换交付形态，不是性能优化。

## 3. 零成本前提诊断（已执行，纯 CPU，不启动实验）

`tools/blank_gov/p229_j1j2_probe.py`，收据 `artifacts/metrics/blank-gov/p229-j1j2-probe.json`。
用 `p188_logp_p184.pt`（dev 515 句后验）+ dev 标注，标准 CTC Viterbi 强制对齐
（扩展状态 `[blank, g0, blank, ..., blank]`），统计 spike 帧数与按 spike 中点切分的连续区间。

| 诊断 | 判据（写死） | 实测 | 结论 |
|---|---|---|---|
| **J1** 片段库可行性 | 区间中位 ≥16 输入帧 且 ≥8 帧占比 ≥0.80 | spike **1.0 帧/词**（均值 1.078，与 D3 的 1.06 互证）；但**区间中位 8.00 编码器步 ≈ 31.48 输入帧**，p10 4 步、p90 14 步，**99.26%** gloss ≥8 输入帧 | **`CLIP_BANK_FEASIBLE`** ✅ |
| **J2** 拒识可行性 | \|ρ\| ≥0.30（负向）且 70% coverage 下 WER 相对降 ≥25% | ρ = **−0.4924**；WER 34.06% → 28.69%（**−15.75%**） | **`STOP`** ❌ |

**J1 的意义**：D3 的「每词仅 1.06 帧被监督」说的是 **spike 帧**，
但强制对齐给出的**连续区间**（含过渡帧）远宽于此 —— 所以「切不出片段」的担忧不成立，
K1 的关键前提通过。阈值 16 输入帧的依据【间接】：arXiv:2401.05336 在 CSL-Daily 用
16 帧滑窗做 ISLR 即达 WER 29.3%。

## 4. K1 执行顺序（全部预注册后再启动）

```
J1 ✅ 已过线（零成本 CPU）
A   train 全量 CTC 强制对齐 -> per-gloss RGB 片段库
    （复用 p222 的 batch1 / MAX_T400 / synchronize / 分片断点 / 自动重试）
B   本地 Qwen2.5-1.5B 生成新 gloss 句（corpus-anchored、词表约束、低频优先、
    dev/test 精确重复排除、数量与种子写死）
C   随机取实例直接拼接（不做边界平滑）-> 合成 RGB 视频 + 新标签
D   固定混合比例下 6 轮 PEFT（P184 配方单变量）-> 统一 R1-R8 判定
     + uWER / 低频桶单独 bootstrap -> 阶段报告
```

任一步落在 dev 噪声地板 ±0.77pp 内即判「无差别」，不进 test。
所有新实验仍必须同时报 `WER_official + uWER + 低频桶 + 高频桶 + ins/sub/del + micro`。

## 5. 诚实预期与收尾条件

- **最大风险**：文献收益在 SLT（语言依赖建模），我们是 CTC gloss 识别（条件独立），
  「新上下文」的收益机制可能不成立；且 6 轮 PEFT 预算短、合成分布有偏移风险
  （E1 / P202 的强增广曾明确负向）。
- **乐观情形**：uWER / 低频桶改善 ≥2pp 而总量与高频桶不恶化；
  **悲观情形**：与 E1 同构的类别间重分配或直接变差。
- 按累计 14 连败的轨迹，K1 落噪声内概率不低。但它是**唯一**满足
  「改数据分布 / 不违反协议 / 有直接 CSLR 与 SLT 文献 / 前提诊断已过线 /
  本地工程基础齐备」的未试方向，性价比高于任何第六次的轻量改动。
- **若 K1 也判负**：合理结论是**接受天花板收尾**，而不是继续找新损失项。
  天花板不变：官方 @224 零样本 test **32.74** / P184@160 test **33.98** / P150 **53.73**；
  唯一稳定正向仍是 P184 冻结主干 PEFT。
