## 1. 关键修复：CTC target off-by-one（P23）

**Bug**：`dataset.py:collate_samples` 把词表索引（0 起）当 CTC 类索引传入，
缺 `+1`。类 0 是 blank，故词表索引 i 必须映射为类 i+1。

**修法**：`flattened.extend(token_id + 1 for token_id in sample.token_ids)`

| | 8 样本 400 轮 | dev 514 / 30 epoch |
|---|---|---|
| | WER / 完美解码 | WER 严格 |
| 修复前 | 0.8947 / 0-of-8 | 0.9760（配置 A） |
| 修复后 | **0.0000 / 8-of-8** | **0.7019**（配置 A） |

P18/P24 三配置对照（均为修复前的 30 epoch，仅 A/B 有修复后数据）：

| 配置 | 词表 | 层级 | `<unk>`率 | n_distinct | 输出长度 | 指标 |
|---|---|---|---|---|---|---|
| A | 301 | token | 0.283 | 6 → 203 | 1.48 → 2.46 | WER 0.9760 |
| B | 3517 | token | 0.000 | 6 → 490 | 1.48 → 4.09 | WER 0.9813 |

## 8. 最有把握的三条判断

### 8.1 唯一真正的改进是修 bug，不是任何优化方案

**数据**：P23 修一个字符（`+1`），dev 严格 WER 0.9760 → 0.7019。
同期所有"优化"方向的幅度：P28 训练时长 -0.0063、P30 容量 +0.0162、
P29 ST-GCN +0.037（更差）、P35 增强 -0.0060、P34 面部 1.01x、P36 RGB 1.60x。

**判断**：这个项目的瓶颈**从来不在模型或特征，而在代码正确性**。
修 bug 带来的 0.274 WER 改善，超过 P0→P23 之间全部 28 份收据里
所有优化尝试的幅度之和（且其中多数为负）。
如果在 P0 之前就先做 8 样本过拟合自检，那 28 份收据中大部分不必做。

我在 P29、P33、P36 三次踩到过"不同配置给出逐位相同数字"这个信号，
每次都指向评估代码有问题——**但我从没把它升华成"先验证管线"这条原则**。
真正做 8 样本过拟合自检是到 P20 才发生的，而那时已经在错误基础上走了 20 轮。

### 8.2 现有特征无法区分 gloss —— 这条我认为是可靠的

**数据**（四组独立测量，同一方向）：

| 测量 | 手段 | 结果 |
|---|---|---|
| P38 | macroAUC（对不均衡稳健） | full368 = 0.6091 |
| P37 | Cohen's d（不依赖分类器） | hands **-0.0171** |
| P30 | 11-100 频次桶 WER | 0.9178 |
| P34 | heldout acc vs 基线 | 0.0028 vs 0.1823 |

**判断**：`hands` 的 d 是**负数**（同 gloss 反而更不相似），
这不可能是"特征不够好"，而是**特征里没有稳定编码 gloss 身份**的证据。
配合 P30「模型能拟合训练集到 0.0065 但 dev 卡在 0.70」，
说明模型在**记住样本**而非学习可泛化的表征。

**这条的直接后果**：任何"再加一点容量/再扰动一点/再加几个点"的方向都很难见效，
因为不是量的问题。

### 8.3 我此前的核心结论里有一条是错的：P34「所有模态≈随机」

**数据**：P38 实测 full368 的 **macroAUC = 0.6091**，远高于随机 0.5。
而 P34 用 acc 口径报告 0.0028，看着像随机。

**判断**：`acc` 在 150 类极度不均衡的 gloss 任务上**是错误的指标**。
P34 的结论方向可能对（面部确实无用，1.01x 这个倍数是真实对比），
但**它的数据来源被指标掩盖了**。
**这意味着 P30 的「中频词样本量不足」也可能需要用 macroAUC 重新审视** ——
它是用 WER 算的，而 WER 同样受不均衡影响。

## 9. 我认为最有价值的未验证方向

**`body_deltas`（`[312:368]`，56 维）**。

**数据**：P37 中它是全部特征块里 d 最高的（z-score 后 **+0.4796**，
而 hands 只有 +0.0723）；P38 中 `cand_bn`（含它）5 折 CV **0.1052**，
是全部视图里最稳的。

**判断**：它从未被单独研究过，而它恰好同时满足两个条件：
（a）信号强（b）稳定（CV 0.105 < 0.3）。
**这是 P36 之后唯一有稳定正信号的方向。**

**但我必须同时说另一面**：
P38 验证 2 显示 `cand_bn` 的 **macroAUC 只有 1.05x**（0.6421 vs 0.6091），
未达我预注册的 2x 阈值。**而 acc 说 3.67x。**
这两个口径方向相反 —— acc 受多数类主导（基线 0.1647），
所以 3.67x 很可能只是"更会猜高频词"。
**而 P30 实测真正的主要误差在 11-100 频次桶，不在高频词。**

**所以我现在的判断是：值得做一次 CTC 消融验证，但不能预期它解决识别问题。**
理由是 macroAUC 提升有限（+0.033），而它是三个口径里最可信的那个。

## 10. 我认为应该停止投入的方向

| 方向 | 判断 | 依据 |
|---|---|---|
| 面部扩容 | 停止 | 128 vs 8 点 = 1.01x，环境已打通但结论明确 |
| 数据增强 | 停止 | 最好的 combo 只 -0.0060，且 train 恶化 58% |
| ST-GCN / 拓扑 | 停止 | train 拟合到 0.0000 但 dev 差 0.037，过拟合加剧 |
| 容量控制 | 停止 | 4 配置全劣于 base，最优差距 +0.0162 |
| 加训练轮数 | 停止 | 30→150 轮只值 0.0063 |
| RGB / CLIP 跨模态 | 停止 | d=0.1006 极弱，heldout 0.0222 远低于基线 0.1833 |
| **换特征提取器（HaMeR 等）** | **暂缓** | 见下 |

**关于 HaMeR**：我此前建议过，但现在判断变了。
P34 已证明**即使加了 128 个面部点，可分性几乎不变（1.01x）**。
HaMeR 是更好的手部特征，但**如果"手部特征不够精细"不是瓶颈，换提取器收益有限**。
且从 P32 的实测看，mediapipe 0.10.35 已移除 `solutions.holistic`，
换 HaMeR 意味着整个提取链路重写 + 全量重提（train+dev 约 5500 视频，3.5 小时）。
**我建议在 macroAUC 口径下先做小规模探针再决定，不直接投。**

---

## 11. 我认为最该做的一件事

**用 macroAUC 重新校准 P30 的"中频词样本量不足"这个结论。**

**理由**：
- P38 证明 acc/WER 在这个任务上会掩盖真实信号（full368 macroAUC 0.6091 但 acc 0.0260）
- P30「中频词样本量不足」是**目前对"为什么 WER 上不去"最有力的解释**，
  且被写进过长期记忆、影响过多个后续实验
- 但它是**用 WER 算的**。如果 WER 口径与 acc 一样失真，
  那这个结论的地基可能不稳

**成本**：零训练，全部基于已有特征重算分桶指标。半小时内能出结果。
**收益**：如果结论翻转，前面六轮实验的归因都要重写；
如果成立，那它是目前唯一站得住的瓶颈诊断。

## 12. 关于这套方法论的三条自我批评

### 12.1 我花了太多轮次才做最基础的验证

P20 的 8 样本过拟合自检应该在 P0 之前做。
P0 到 P23 之间共 **28 份收据**（p0 / p1 / p2-frame-level / p2b / p3 / p5 /
p6 ×2 / p7 ×2 / p8 / p9 / p10 / p11 / p12 / p13 / p14 / p15 ×4 / p16 / p17 /
p18 ×3 / p19 / p20 / p21 / p23）建立在这个 off-by-one 之上，
其中 P11/P12 后来已自行作废并用真实数据重做。
我在 P29、P33、P36 三次踩到过"不同配置给出逐位相同数字"这个信号，
每次都指向评估代码有问题 —— **但我从没把它升华成"先验证管线"这条原则**。
真正做 8 样本过拟合自检是到 P20 才发生的，而那时已经在错误基础上走了 20 轮。

**根因**：我把"论文里有没有这个方法"当成了默认的优先级，
而没有把"我的实现是否正确"放在更前面。

### 12.2 探针设计错误重复了三次

| 轮次 | 错误 | 我花了几轮才发现 |
|---|---|---|
| P29 | 参考口径用 CSV gloss，与训练 target 不同源 | 1 轮 |
| P33 | 50 视频只有 3 个可评估类，探针饱和 | 1 轮 |
| **P19/P31/P34** | **整句池化，任务本身不可解** | **直到 P36 才系统性纠正** |

**第三个是根本性的**：我用了 5 轮实验（19/31/34/36 才意识到）
去测量一个**定义上就没有答案的任务**。

### 12.3 我引入了一个自己没意识到的偏差

写实验脚本时我曾用"合成数据"做功能测试，
并在 P11/P12 把**理论公式**和**合成概率矩阵**的结果当成了真实效果，
报告了 SCP 的正信号。那是错的，后来作废并用真实数据重做（P13/P14）。

**判断**：这次经历说明，在小数据集上，
**"看起来合理的数字"很容易来自我自己的实现假设，而不是数据**。
所以我在汇总里坚持把所有数字都标上来源收据，不使用记忆中的值。

## 13. 一句话总结

**这个项目真正的进展是：找到了并修掉了一个使所有历史实验失效的 bug，
并在修好后系统性地排除了 7 个方向。**
它没有把 WER 降到可用的水平（0.70 严格），但它明确了"下一步不该做什么"，
并且发现此前用错了指标 —— 这可能比任何一次优化都更有价值，
因为它意味着之前几轮"无效"的结论里，可能有一部分是被错误指标掩盖的。
